# Eval findings

What the measured sweeps established. `SWEEP.md` and `TRIGGERING.md` beside this file are
generated by `scripts/eval_report.py` and are not written by hand.

The harness is `claude plugin eval`, driven by [`scripts/run_evals.py`](../scripts/run_evals.py).
See [Evals](../README.md#evals) for the axes, [README.md](README.md) for the case layout, and the
`skill-authoring` skill for the thresholds that settle a verdict.

## Findings that survive the harness

These came from the custom Python harness that `claude plugin eval` replaced. Each one is a
property of the skills or of headless measurement, and not of the runner, so each one still holds.

**A dialogue-first skill scores a negative delta in a one-turn run.** `decide` measured **-25.5%**
once the skill was forced to load, because it correctly opened with a framing question and that
question was the whole one-turn answer. The fix is one sentence appended to the prompt: *"Do not
stop and wait for me. Put your questions and your full answer in this one reply."* It forbids
waiting without forbidding asking, which matters because several suites score the question itself.
Re-measured, `decide` went to **+19.3%**, and its fourth case went from 0/8 to 8/8. That sentence
is now in 14 prompts across four suites. Do not remove it, and do not assume `max_turns` replaces
it: a turn cap stops the run, it does not stop the skill from waiting.

**Probe fixtures decide the triggering score.** Seeding the working directory with what a probe
prompt names moved recall from 58/96 to 78/96, cutting misses from 38 to 18. A probe that names
`docs/decisions/DR-0004` and finds no such directory measures a missing directory, not the skill
description. Every probe suite carries a `triggering/probe_fixture.sh` for this reason.
`review-feature-suite` lost a hold once its fixture existed, which exposed a real description gap
rather than a measurement artifact.

**Two skills cannot be measured on their read path.** `pr-review` and `address-pr-comments` read
through `mcp__glab__glab_api`. No plugin here ships an `.mcp.json`, so `claude plugin eval` starts
no MCP server and the tool is absent; the model has to fall back to a `glab` Bash call for the run
to reach the stub CLI. The write path is covered, because the stubs log every write and answer with
a canned success. `mocks/` does not help until a plugin declares the server itself.

**Grafana has no case at all.** It is reachable only over MCP, and no stub can stand in for it, so
the `triage-work-item` suite drives CloudWatch, which is a CLI, instead.

**`implement-scenarios` mandates a blocking `AskUserQuestion`.** That is unusable in a headless
one-turn run, so every one of its cases works around it. The skill is right and the measurement is
the thing that cannot follow.

**No test framework is installed in a run.** `review-changes` cases 2 and 3 therefore only reach
the "reported as unverified" half of the behavior they describe.

**A slash command injects the skill body and makes no `Skill` tool call.** Proved by token count:
`decide` at 5108 bytes adds about 1494 tokens. So a `tool_used: Skill` grader can never confirm
that a slash-command prompt loaded the skill. This is why the three Manual skills are tagged
`mechanics` and carry no firing indicator.

## What the migration to `claude plugin eval` changed

**The baseline arm can no longer be forced to load the skill.** The old harness prefixed
`/decisions:decide` onto the with-skill arm only, which measured behavior in isolation.
`claude plugin eval` sends one prompt to both arms, so the with-plugin arm loads the plugin and the
model still decides whether to reach for the skill. Behavior and triggering are now measured
together on the `behavior` axis.

`decide` quantifies the difference exactly. The two cases where the skill fired returned **+0.20**
and **+0.17**, which reproduces the old forced-load figure of +0.193. The two cases where it did
not fire returned **0.00**, pulling the suite mean to **+9.2%** (85.1% with, 76.0% baseline, fired
2/4). Read the `Fired` column before the delta: a zero delta on a case that never fired says
nothing about the quality of the skill body, and everything about its description.

**The suites moved out of the plugins.** They live at `evals/<plugin>/<skill>/` in the repository
root. Claude Code copies a plugin's whole directory into its install cache, so a suite kept inside
a plugin shipped to every user who installed it: `agent-docs` carried 233 files of which 229 were
eval cases, and the skills themselves were 4. Each case names its plugin in its `plugins:`
frontmatter, and `claude plugin eval` resolves it from out there, which is verified.

**Isolation stopped being destructive.** The old harness moved `~/.claude/skills`, `~/.claude/rules`
and `~/.claude/CLAUDE.md` aside and blanked `enabledPlugins` and `skillOverrides` in the real
settings file for the length of a sweep, which made the machine unusable for ordinary work and made
CI impossible. `claude plugin eval` gives every run its own `HOME`, its own `CLAUDE_CONFIG_DIR`,
its own `TMPDIR` and `--setting-sources user`, and loads only the plugin under test. Nothing is
moved and nothing is blanked.

**Triggering got better, not just cheaper.** `decide` measured **Fires 8/8 · Holds 8/8** against
7/8 · 8/8 under the old harness, at $1.92 for 16 probes.

## Measured cost, at one run per case

| Axis | Units | Measured | Projected |
|---|---|---|---|
| behavior | 55 cases x 2 arms | $2.46 for 4 cases | about $34 |
| mechanics | 16 cases x 1 arm | — | about $8 |
| triggering | 192 probes x 1 arm | $1.92 for 16 probes | about $23 |

About **$65** for a full sweep. Pass `--max-cost-usd`; a run that hits the ceiling still writes its
document and marks it `partial`, and a partial document is not a measurement. Re-run only the
verdicts that land near a threshold at `--runs 3`.

## State

`decide` is the only skill measured on the new harness, on both axes, so it is the only entry in
`README.md` that carries a score: `+9 pts vs. no skill`, from **+9.2%** over 4 behavior cases. The
other 14 carry converted suites that have not been run, and an unmeasured skill carries no score
rather than a figure from the old harness. Run the full sweep to fill them in.
